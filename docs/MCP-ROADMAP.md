# MCP 当前能力与后续补齐顺序

观澜 MCP 的定位是让自己的 Agent 读取带日期、口径和证据的市场资料，而不是再做一层不透明的选股结论。优先补齐个股证据、资料时效和资金解释，再扩大覆盖。

本说明更新于 **2026-11-17（北京时间）**。下面明确区分已开放与规划；没有上线日期承诺，不因写入文档就自动开放权限或执行任务。

## 先分清两个 MCP

- **线上观澜 MCP：** 独立服务，外部客户端以观澜账号完成 OAuth 后按授权范围使用。当前已申请的已知权限默认全选，可取消，点击允许后才生效；旧授权和未来未知权限不自动扩大。正式服务地址为 `https://guanlan-research.kunkun1023.xyz/mcp`，工作台入口为“观澜 MCP”。
- **Harness 本轮证据 MCP：** 本地研究运行时的 `guanlan-evidence`，只提供 `list_evidence`、`read_evidence`、`read_methodology`，读取本轮已准备的证据；不是完整市场接口，也不是任意 Shell／文件入口。

本地工作台已经能阅读某类页面，不等于线上 MCP 已导出该页面全部接口；本地 Agent 能自行联网，也不等于它自动拥有全部观澜共享资料工具。

## 第一优先级 先让资料读得准

| 待补能力 | 为什么值得做 | 验收重点 |
| --- | --- | --- |
| 统一资料状态与时效查询 | Agent 先知道最新交易日、报价时间、龙虎榜披露截止日、缺档及失败保留情况，再决定读什么 | 不用服务器当前时间冒充资料日；区分休市、延迟、未发布、缺档和失败；复用共享状态，不重抓全市场 |
| 股票与板块身份检索 | 从名称、代码找到稳定身份，避免同名股票、概念和跨来源板块混用 | 返回市场、品种、来源与代码；歧义要求确认，不凭名称合并 |
| 独立个股报价与K线读取 | 外部 Agent 能核对当前价格、复权趋势和量价，而不是只能从筛选表间接取得 | 明确周期、复权、成交量单位、报价日与缓存；限制根数和批量规模，历史不混入未完成周期 |
| 个股公开证据包 | 汇总已有公告、财务、主营、估值、资金与产业关联，让个股研究不只靠目录和标签 | 每项给来源、报告期、资料日、缺失与原文入口；不附带个人持仓成本，不为读取自动生成平台报告 |
| 统一口径与来源说明 | Agent 能解释主力资金、机构净额、单日／累计、前10上榜等含义 | 金额单位、公式、窗口、去重和覆盖可查；换源不假装同一序列延续 |
| 原生客户端兼容与排错 | 让用户能判断配置、授权和实际取数分别卡在哪里 | Codex／WorkBuddy 等各跑真实授权与读取；过期、撤销、断网、限流、超限均明确反馈，不将“已授权”写为“已连接” |

## 第二优先级 把看盘和研究链条补完整

| 待补能力 | 用法与边界 |
| --- | --- |
| 独立板块资金观测 | 导出已有行业／概念资金方向、排名、成员集中度及重叠提示；不与龙虎榜机构足迹混称。不同源、不完整窗口分别返回 |
| 机构席位逐日原始依据检索 | 当前足迹已有逐日摘要，下一步提供更通用的按股票／日期／席位筛选；保留单日与累计区间、去重及历史身份关联的不确定性 |
| 公告与财务定向检索 | 按公司、报告期、公告类型或关键词查询已有索引和可用正文；目录、摘要和已取得正文分开，防止只看标题形成确定结论 |
| 产业链与公司横向筛选 | 从已发布研究中按环节、业务角色和证据状态查公司；区分直接业务、间接受益与待核验，不把概念成分当成真实订单 |
| 最新发布与资料更新摘要 | Agent 只读取上次之后已更新的共享版本，减少重复大结果；失败明确保留原版，先保证最新滚动，不先做复杂跨日对比系统 |
| 有界多模块观察包 | 一次读取同一观察时点的市场、情绪、题材和资金摘要，并返回各自日期／版本差异；不能把异步披露强行伪装成同一时点 |
| 更丰富的使用模板 | 基础 Prompts／Resources 已开放；后续按实际使用补充更多研究路径，模板不暗中运行研究或调用平台模型 |

## 后续按需求开放 不默认扩大权限

| 方向 | 前置条件 |
| --- | --- |
| 自己的知识与战法辅助筛选 | 先定义可核验规则、主观判断和缺项；本地知识按选择提供，不把本地文件库默认上传到 SaaS |
| 个人自选、持仓或笔记只读访问 | 另设明确的个人资料授权，可撤销、账号隔离；研究报告存取已按上方独立范围开放，共享资料授权不自动获得私人访问 |
| 笔记、提醒及更多资料操作 | 新增自选／持仓已按独立范围开放；笔记、提醒、修改或删除仍未开放，须另行设计授权、确认、幂等和操作留证 |
| 自己的 Agent 定时复盘与通知 | 用户主动安排，并明确执行设备、资料权限、模型费用及通知渠道；先有失败／取消／中断恢复策略，不因读取自动开始后台研究 |
| 更多来源与客户端 | 在许可、单位、日期和失败恢复核验通过后再加入；不能把原始源增加数量当作质量证明 |

交易、自动下单、任意 SQL／URL 代理、服务器 Shell 和不受控文件访问不属于这条 MCP 路线。资料写入不是交易执行。观察规则不承诺收益，历史统计不当作未来胜率。

## 每次新增能力的验收底线

1. **同源同版：** 和工作台同版共享成品一致，分页固定版本；日期、单位、来源、缺项不丢失。
2. **时效优先：** 默认取最新可用滚动资料，旧档按需读取；缺档不临时全市场回补、不以历史冒充当前。
3. **只读与授权：** 账号范围、到期、撤销、原会话失效和限流均验；个人资料不夹带，模型不被静默调用。
4. **有界响应：** 参数、批量、分页和单次容量明确；超限缩小范围或分页，不静默截断导致结论偏差。
5. **失败保留：** 重复读取不重复生成；源失败、超时和中断不触发自动付费重跑，旧数据与日期可辨。
6. **真实验证：** 自动化回归之后再做已授权范围内的真实客户端验收；未验证的客户端、资料期和状态明确列出。

建议实施顺序：**时效与口径 → 身份检索 → 个股报价／K线／证据 → 板块资金与公告财务 → 产业横向筛选与增量摘要**。个人资料、写入及定时任务另立授权，不为补接口一次性做复杂平台编排。
