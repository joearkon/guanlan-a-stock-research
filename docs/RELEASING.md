# 仓库更新与发布约定

每次向 GitHub 交付更新，都同步维护根目录 [CHANGELOG.md](../CHANGELOG.md)。读者应能看出改了什么、如何验证、是否需要更新，以及哪些部分仍未验证。

## 每次更新

1. 在“未发布”下记录用户可感知的新增、修复或文档变更；与同一功能相关的小修合并描述，不逐条复制提交消息。
2. 完成交付前，以北京时间日期归入对应条目，并列明本批验证范围和已知限制。正在开发或验收失败的内容留在“未发布”，不能写成已交付。
3. 更新日志与相应代码或文档同批提交、推送。纯文档修改不冒称重新完成模型、行情或全应用回归。
4. 已发布批次不追加新功能，也不改写当时的验收结论；更正错误时明确说明。小修可在本日新增小节，不能只更新代码而遗漏日志。

## GitHub Releases

- 每个可交付批次发布一份摘要；一个批次可包含多次提交，不为修正错字反复创建版本。
- 开发预览使用 `v0.1.0-dev.YYYYMMDD.N` 标签并标记 **Pre-release**，标签指向实际已推送的提交。它表示源码预览批次，不代表应用已成为稳定版或线上 SaaS 已更新。
- Release 摘要包含新增/修复、验证范围、已知限制和完整更新日志链接。只发布实际存在且已核验的安装包或附件；只有源码时明确写明。
- 发布前查看现有标签与 Release。中断后先核对是否已创建，不能重复发版、移动已发布标签，或覆盖其他人的 Release。
- 仅在用户授权的交付范围发布仓库版本；GitHub 发布不授权部署 Cloudflare、调用模型或修改真实个人数据。

## 版本边界

本仓库重点是 Local Harness。涉及线上 SaaS、MCP 或共享数据服务时，必须单列实际部署版本和验收状态；仅讨论、规划或本地适配不能标记为线上已发布。后续计划继续放在 README 的开发计划中。

更新日志与 Release 不包含凭据、邮箱、个人持仓成本、私人报告或原始 QA 日志。测试详情链接到可公开的验收说明，不上传本机私有产物。
